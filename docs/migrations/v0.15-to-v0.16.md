# Migrating from v0.15 → v0.16

`react-native-image-stitcher` v0.16 ships the first-time-user panorama
capture **guidance** set and changes three pieces of default behaviour.
None of these are large code changes for a host app, but each can alter
what the user sees or what `onCapture` receives, so read the three
sections below before upgrading.

> [!IMPORTANT]
> v0.16 is a MINOR bump on the 0.x line, which is API-unstable by design
> (see the top of `CHANGELOG.md`). The breaking changes are behavioural
> defaults plus the `onCapture` result shape — there is no automated
> migration helper.

---

## 1. `onCapture` is now a discriminated union keyed on `ok`

`onCapture` fires once per capture attempt — on **success** (`ok: true`)
AND on **failure** (`ok: false`, carrying `error: CameraError`).
Previously it fired only on success and failures went solely to
`onError`. `onError` still fires on failure as an unchanged mirror.

```tsx
// ❌ v0.15 — assumed success
onCapture={(result) => {
  setImage(result.uri);
}}

// ✅ v0.16 — gate on result.ok first
onCapture={(result) => {
  if (!result.ok) {
    handleError(result.error);   // also still delivered to onError
    return;
  }
  setImage(result.uri);          // ok:true — uri/width/height present
  // Both branches also carry result.warnings: CaptureWarning[]
}}
```

New exports: `CaptureWarning`, `CaptureWarningCode`,
`PanoramaCaptureResult`. The two non-fatal warning codes are
`LOW_FRAME_UTILIZATION` (<70 % of captured frames used) and
`LATERAL_DRIFT_FINALIZE`.

---

## 2. `<Camera>` defaults to `panMode='vertical'` (landscape-only)

A panorama now defaults to a **landscape-only, top→bottom** sweep. A
portrait hold is gated behind a "Rotate to landscape" prompt and the
capture starts the moment the user rotates.

| `panMode`      | Hold orientation        | Gated hold shows           |
| -------------- | ----------------------- | -------------------------- |
| `'vertical'` (default) | landscape, top→bottom | rotate-to-landscape prompt |
| `'horizontal'` | portrait, left→right    | rotate-to-portrait prompt  |
| `'both'`       | either                  | no prompt                  |

```tsx
// Restore the pre-v0.16 "accept any orientation" behaviour:
<Camera panMode="both" /* … */ />

// Portrait, left→right panoramas:
<Camera panMode="horizontal" /* … */ />
```

The rest of the guidance set (`panGuidance`, the pan how-to overlay, the
"moving too fast" pill, the blinking countdown + auto-finalize at
`maxPanDurationMs`, the lateral-drift stop at `lateralBudgetCm`) is
opt-out via those props. The optional post-stitch review surface
(`rectCrop` / `showPreview`) is **off** by default — with both off,
`onCapture` fires immediately with no review screen.

---

## 3. Stitch defaults moved to more robust values

| setting                  | v0.15 default | v0.16 default | why |
| ------------------------ | ------------- | ------------- | --- |
| `stitchMode`             | `'auto'`      | `'panorama'`  | the auto-resolver's SCANS branch keys off double-integrated IMU translation, unreliable during rotation |
| `warperType`             | `'plane'`     | `'spherical'` | bounds both axes — fixes fragmented wide / vertical pans |
| `maxKeyframes`           | (looser)      | `8`           | denser, more reliable coverage |
| `maxKeyframeIntervalMs`  | `0` (off)     | `1000`        | 1 s time-budget force-accept re-enabled |
| `overlapThreshold`       | (looser)      | `0.15`        | denser keyframes |

If you relied on the previous behaviour, set the values explicitly.
v0.16 also adds JSON-object config props as the recommended way to do
this (see below):

```tsx
// Restore v0.15 stitch behaviour:
<Camera
  stitcher={{ stitchMode: 'auto', warperType: 'plane' }}
  frameSelection={{ maxKeyframeIntervalMs: 0 }}
  /* … */
/>

// …or via the flat default* props (still supported):
<Camera defaultStitchMode="auto" defaultWarper="plane" /* … */ />
```

---

## New (additive): `stitcher` / `frameSelection` JSON-object props

v0.16 adds two object props that take the full config in one place.
Both are **partial** — set only what you want; everything else falls
back to the flat `default*` prop, then the SDK default. `flow` is
deep-merged, so you can override a single flow knob.

```tsx
<Camera
  stitcher={{
    warperType: 'spherical',
    blenderType: 'multiband',
    seamFinderType: 'graphcut',
    stitchMode: 'panorama',
    enableMaxInscribedRectCrop: false,
  }}
  frameSelection={{
    maxKeyframes: 8,
    overlapThreshold: 0.15,
    maxKeyframeIntervalMs: 1000,
    flow: { noveltyPercentile: 0.85 }, // deep-merged with the rest of flow
  }}
  /* … */
/>
```

Object fields win over the matching flat `default*` props, which remain
supported for backward compatibility.
